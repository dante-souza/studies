O usuário diz o prato, o modelo devolve os ingredientes

Simples de propósito: tudo que dá errado aqui dá errado em qualquer aplicação com LLM.

  usuário ──► "pizza margherita para 2"
                      │
                      ▼
               ┌─────────────┐        o que pode dar errado

                      │               • vocabulário: "cups" em vez de "g"

notebook 02

Uma classe diz o formato e confere a resposta

class Ingrediente(BaseModel):
    model_config = ConfigDict(extra="forbid")
    nome: str
    quantidade: float = Field(gt=0, description="Quantidade numérica, sem unidade")
    unidade: str = Field(description="Unidade métrica: g, kg, ml, l ou un")


class ListaDeCompras(BaseModel):
    model_config = ConfigDict(extra="forbid")
    prato: str
    porcoes: int = Field(gt=0)
    ingredientes: list[Ingrediente]

A mesma classe gera o JSON Schema que vai para o modelo e valida o que volta:

quantidade: {'description': 'Quantidade numérica, sem unidade', 'exclusiveMinimum': 0, 'title': 'Quantidade', 'type': 'number'}

notebook 02

O contrato garante a forma, não o vocabulário

  1. description é pedido, não regra. Com unidade: str, passa ['cups', 'tablespoon'] construído.
  2. Texto em volta do JSON ainda quebra o caminho do schema no prompt (json_invalid). Um extrair_json que pega da primeira { à última } resolve a maioria dos casos.

Falta fechar o vocabulário de cada campo.

notebook 04

O modelo pede, o seu código executa

O modelo não sabe o preço do tomate nem o que tem na despensa. Ferramentas são funções Python comuns que ele pode pedir.

class Ferramenta(StrEnum):
    CONSULTAR_PRECO = "consultar_preco"
    VERIFICAR_DESPENSA = "verificar_despensa"


FERRAMENTAS = {  # nome -> (modelo dos argumentos, função)
    Ferramenta.CONSULTAR_PRECO: (ArgsIngrediente, consultar_preco),
    Ferramenta.VERIFICAR_DESPENSA: (ArgsIngrediente, verificar_despensa),
}
TOOLS = [openai.pydantic_function_tool(args, name=f.value, description=DESCRICOES[f])
         for f, (args, _) in FERRAMENTAS.items()]

O enum é a lista fechada do que pode ser chamado. O modelo Pydantic dos argumentos vira o schema da ferramenta.

O nome do membro (PRECO) pode mudar. O valor ("preco") é contrato com o mundo de fora.

O modelo propõe, o código decide

            o modelo PROPÕE                         o código DECIDE
  ┌───────────────────────────────┐      ┌──────────────────────────────────┐
  │ JSON no formato do schema     │ ───► │ Pydantic: forma e tipos          │
  │ valores do enum               │      │ Enum: vocabulário fechado        │
  │ pedido de ferramenta          │      │ guardrail: existe? args batem?   │
  │ intenção e confiança          │      │ regras, limites, rota, permissão │
  └───────────────────────────────┘      └──────────────────────────────────┘
  1. Prompt informa, código garante. Description, instrução e schema são pedidos ao modelo.
  2. Erro silencioso é o pior erro. '250 grams250 grams' e rotular(...) -> None não levantam nada.
  3. Erro de validação é feedback. Volta ao modelo em vez de derrubar o programa.
  4. Toda tabela por enum precisa de teste de cobertura. Rotas, ferramentas, permissões.
  5. O valor do enum é contrato externo. Renomeie o membro, nunca o valor.
